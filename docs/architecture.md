# 可恢复架构

## 运行形态

```text
浏览器
  └─ FastAPI 同源页面（静态 HTML / CSS / JS）
       ├─ /api/chat：推荐、会话状态、预算/库存/尺码硬校验
       ├─ /api/profiles：匿名个人档案
       ├─ /api/profiles/{id}/wardrobe：我的衣橱
       └─ /api/profiles/{id}/calendar：穿衣日历与月度统计
            └─ SQLite（本地开发）/ PostgreSQL（生产替换目标）
                 └─ Excel 商品更新源（启动时导入 70 条）
```

## 边界原则

- 前端只渲染 API 返回的本轮状态；无匹配与场景冲突不复用旧推荐卡。
- 价格、库存、在售、尺码、预算和禁忌品类由后端硬校验，不由浏览器决定。
- `profile_id` 是浏览器生成的匿名隔离键，不是登录体系；生产多用户场景需要替换为真正的认证身份。
- 个人档案、衣橱、日历均为用户主动录入数据，不采集定位或真实天气。

## 当前可恢复性等级

| 资产 | 状态 | 恢复方式 |
|---|---|---|
| 后端与网页 | 已代码化 | 从 GitHub 克隆后启动或 Docker 构建 |
| 商品种子数据 | 已代码化 | Excel 自动导入 |
| 数据表结构 | 已代码化 | SQL 迁移文件与启动时幂等建表 |
| 运行数据 | 本地 SQLite 不提交 | 生产须使用受管数据库备份 |
| 秒哒内部实现 | 无法自动导出 | 本仓库以可运行的本地重建版本替代 |

## 生产演进

1. 将 SQLite Repository 替换为 PostgreSQL Repository，并把 `0001_initial_schema.sql` 纳入迁移工具。
2. 使用 GitHub Actions 的验证工作流作为合并门禁。
3. 将 Docker 镜像部署到独立云端，配置健康检查 `/health` 与 `/ready`。
4. 接入受管数据库每日备份、错误告警和部署回滚。
